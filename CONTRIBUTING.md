# Contributing to azuline

Thank you for wanting to help. azuline is built by one developer, so a review can take a few days.

## Before you start

- Search the existing issues first.
- For anything bigger than a small fix, open an issue and describe the change before writing code, so nobody
  spends a weekend on something that can't be merged.

## What we won't merge

- Generative AI features of any kind: generating or extending images, style transfer, upscaling, denoising,
  background removal, colourising, line cleanup, AI critique and AI-detection scores.
- Images, icons, illustrations or sample art made with generative AI. Every image in our repositories is made by a
  person and comes with its licence and credit.
- Anything that sends images, file names or library contents off the user's computer without the user choosing
  to share or sync.
- Analytics fields that aren't on the published list.

## Code

You can write code with any tools you like. You're responsible for every line you submit: you understand it,
you've run it, and you have the right to contribute it.

- Keep a pull request to one change.
- Write commit messages that say what changed and, if it isn't obvious, why.
- Each repository's README lists the commands for building, testing and formatting.

## Sign-off

We don't use a contributor licence agreement. Instead, every commit ends with a sign-off line confirming you have
the right to submit it under the repository's licence, as set out in the
[Developer Certificate of Origin](https://developercertificate.org/):

```
Signed-off-by: Your Name <you@example.com>
```

`git commit -s` adds the line for you. Contributions come in under the licence of the repository you contribute
to.

## Translations

Translations open once the app has text to translate. English and Russian are kept up to date by the project.

## Conduct

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md).
